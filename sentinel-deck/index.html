03 / 19

Sentinel-AI: A High-Performance, Microservices-Based Hybrid Architecture

Designed to integrate 80,000+ CCTV nodes without replacing existing hardware or VMS infrastructure.

01 · Video Ingestion & WebRTC Streaming

RTSP feeds over TCP via OpenCV, transcoded to WebRTC via MediaMTX for ultra-low-latency browser playback.

02 · Dynamic Geo-Fenced AI Micro-Agents

Spawned within a 5km radius of a reported incident using PostGIS spatial queries — not continuous 24/7 scanning.

03 · Dual-Mode Analytics

Targeted single-vehicle deep search alongside automated batch-logging for real-time watchlist cross-referencing.

04 · Database Partitioning & Redis Caching

State-code sharding (GJ01, GJ04…) with in-memory Redis lookup for target sub-millisecond vehicle queries.

05 · Decoupled Web Architecture

Frontend/APIs kept fully separate from heavy AI compute, protecting dashboard uptime under heavy AI load.

Zero-hardware-overhaul approach — direct RTSP ingestion, no camera replacement

Core AI Innovation
06 / 19

Instead of Searching the Whole City, Search Where It Matters

An incident — a watchlist hit, a flagged plate, or a manual investigator query — triggers agent spawning. Using PostGIS spatial queries against camera GPS metadata, Sentinel identifies all cameras within a 5 KM radius of the trigger location and spins up lightweight detection workers scoped only to those feeds. Agents release back to standby after an idle window with no new activity.

Conventional Approach

Full-Network Continuous Processing

Runs heavy AI models on all 80,000+ camera feeds simultaneously, 24/7.

Massive server cost, excessive power consumption, high latency.

Sentinel Agentic Approach

Dynamic 5 KM Geo-Fenced AI Micro-Agents

When an incident triggers, Sentinel spawns lightweight AI agents assigned specifically to nearby cameras within a 5 KM radius.

Simple Analogy: Deploying investigators to the scene instead of searching the entire state.

Target Architectural Outcome: Up to 90%+ target reduction in continuous AI compute load. (Proposed design target)
Operational Flexibility
07 / 19

Dual-Mode AI Analytics: Two Ways of Looking at Vehicles

Both modes operate concurrently on the unified Sentinel ingestion backbone.

Mode 1 · Targeted Investigation

Triggered for a specific target vehicle (e.g., license GJ01AB9999). Full computer-vision pipeline — occupant detection, driver crops, deep tracking — activates only within an active 5 KM incident zone.

  • Search specific camera feeds
  • Reconstruct movement history
  • Extract driver/occupant crops
Use Case: High-priority active crime response.
Mode 2 · Continuous Vehicle Logging

Background recording of passing vehicle observations, using a lightweight, plate-only detector — cheaper than Mode 1's full pipeline, so the 90%+ compute-savings target holds even while every camera logs continuously.

  • Index plate + time + junction
  • Cross-reference with watchlists
  • Instantly match suspicious plates
Use Case: Watchlist alerts & audit trail history.
Dual-mode design preserves the geo-fencing compute-savings target
