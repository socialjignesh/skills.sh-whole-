02 — Proposed Solution03 / 19

Sentinel-AI: A High-Performance, Microservices-Based Hybrid Architecture

Designed to integrate 80,000+ CCTV nodes without replacing existing hardware or VMS infrastructure.

01 · Ingestion

Video Ingestion & WebRTC Streaming — RTSP feeds over TCP via OpenCV, transcoded to WebRTC via MediaMTX for ultra-low-latency browser playback.

02 · Agents

Dynamic Geo-Fenced AI Micro-Agents — spawned within a 5km radius of a reported incident using PostGIS spatial queries, processing temporally-skipped frames (5 FPS).

03 · Analytics

Dual-Mode Analytics — targeted single-vehicle deep search alongside automated batch-logging for real-time watchlist cross-referencing.

04 · Data Layer

Database Partitioning & Redis Caching — state-code sharding (GJ01, GJ04…) with in-memory Redis lookup for target sub-millisecond vehicle queries.

05 · Architecture

Decoupled Web Architecture — frontend and APIs kept fully separate from heavy AI compute, protecting dashboard uptime even under heavy AI processing load.

04 — Core AI Innovation06 / 19

Instead of Searching the Whole City, Search Where It Matters

An incident — a watchlist hit, a flagged plate, or a manual investigator query — triggers agent spawning. Using PostGIS spatial queries against camera GPS metadata, Sentinel identifies all cameras within a 5km radius of the trigger location and spins up lightweight detection workers scoped only to those feeds, processing temporally-skipped frames (5 FPS) from live streams and local VMS recordings. Agents release back to standby after an idle window with no new activity.

Conventional Approach

Full-Network Continuous Processing

Heavy AI models run on all 80,000+ camera feeds simultaneously, 24/7. Massive server cost, excessive power consumption, high latency.

Sentinel's Approach

Dynamic 5km Geo-Fenced Micro-Agents

Lightweight agents spawned only within a 5km radius of a triggering incident — investigators deployed to the scene, not searching the entire state.

90%+ Infrastructure Cost Savings (Architecture Design Target) — event-triggered geo-fenced agents vs. continuous statewide scanning
05 — Operational Flexibility07 / 19

Two Ways of Looking at Vehicles

Both modes run concurrently on the same unified ingestion backbone.

Mode 1

Targeted Investigation

Full computer-vision pipeline — occupant detection, driver crops, deep tracking — activates only within an active 5km incident zone. Triggered for a specific target vehicle, e.g. GJ01AB9999.

  • Search specific camera feeds
  • Reconstruct movement history
  • Extract driver/occupant crops

Use case: high-priority active crime response.

Mode 2

Continuous Vehicle Logging

A lightweight, plate-only detector runs across all feeds in the background — cheaper than Mode 1's full pipeline, so the 90%+ compute-savings target holds even while every camera logs plates continuously.

  • Index plate + time + junction
  • Cross-reference with watchlists
  • Instantly match suspicious plates

Use case: watchlist alerts & audit trail history.
